# Plate: read this first

Plate is a local learning app for Richard Camacho. It is a small CAD window for one kind of part: a rectangular plate a 3-axis mill could cut. The drawing is the product. Grok can edit the part by calling tools. C# decides whether a tool call is legal, stores the part with its revision history, and writes the G-code. C# also calls the xAI API. There is no Python service.

This file is the map for any later agent. Read it before writing code. Then read the doc for the area you are about to touch. Do not invent a second architecture.

Also read `AGENTS.md` and `/Users/richard/Desktop/coding-practices.md`. Richard approved `docs/design-artifact.md` on 2026-11-13.

Status (2026-11-13): design artifact approved. The five decisions below are locked. Figma file `space_x_proj`, page `Plate`, has 8 boards built by `design/figma/screens.js`. Compose boots `api` and `web` (health checks, non-root, read-only root, SQLite on `plate-data`). No domain code yet. `.editorconfig` and the gitleaks CI job are in place. The `api` and `images` CI jobs build the health shell and do not push.

## What this is not

- Not a general CAD kernel, and not a clone of Fusion or NX.
- Not the Components team's product. That team writes factory software around parts that already exist in CAD. Plate is a small version of that slice.
- Not flight software. The G-code is a teaching output. The UI must say not to run it on a machine.
- Not a chatbot with a canvas bolted on.
- Not multi-user, and not a network service. It binds to 127.0.0.1.

## Decisions

| Topic | Decision |
| --- | --- |
| Frontend | Angular and TypeScript, standalone components, signals |
| API | ASP.NET Core minimal APIs, C#, current .NET LTS |
| AI | C# calls `XAI_BASE_URL` (default `https://api.x.ai/v1`). No Python process. No SDK. |
| Database | SQLite file on a Docker volume, via EF Core, WAL mode |
| History | Every accepted change is a row in `part_revisions`. Undo and redo are server-side. |
| Concurrency | Every write carries the part `version`; stale → 409. A Grok turn locks its part. |
| Run | Docker Compose: `web` (127.0.0.1:8088), `api` (no host port) |
| Units | Millimeters only. Origin is the lower-left corner of the stock, on the top face. Depth is positive into the material; Z in the program is negative. |
| Part | One rectangular plate. Features: holes, pockets, slots. |
| Who writes G-code | C# only |
| Who validates a tool call | C# only |
| Who holds `XAI_API_KEY` | The `api` container only |
| Look | Tokens in `docs/design.md`. Lime only as the live dot. Red text uses `error-text`. |
| CI | GitHub Actions: lint, build, test, e2e with a stub provider, secret and vulnerability scans |

Why no Python: the xAI API is ordinary HTTP and OpenAI-compatible. A second language would not buy compatibility. C# owns the tool loop so there is one place that can mutate a part.

Why Angular: Richard chose it. It is also the framework SpaceX application software has described publicly, and the one the Components posting names first.

Why SQLite: he wants a database he can run on this machine with no server. SpaceX factory apps have used SQL Server and PostgreSQL. SQLite is the local stand-in, and EF Core keeps the swap to PostgreSQL a provider change.

Why server-side revisions: undo has to cover Grok's edits, survive a reload, and never diverge from what SQLite holds.

## Invariants

1. The browser talks only to the C# API, on the same origin.
2. `XAI_API_KEY` is never in the Angular app, the `web` image, the repo, or a log line.
3. Every geometry change goes through `PartCommands.Execute` → `Apply`. The UI, undo, and Grok all end there.
4. A refused change leaves the stored part and its version unchanged.
5. G-code is generated from the stored part by C#. It is not generated by the model and it is not executed.
6. User text that lands in a G-code comment cannot contain a newline, a parenthesis, a semicolon, or a percent sign.
7. Every number in the program is formatted invariant-culture with three decimals.
8. Units stay millimeters.
9. Model output can only become tool calls. It never becomes SQL, a file path, a shell argument, HTML, or a program line.

## Locked decisions (2026-11-13)

1. After every `T<n> M06`, the next line is `G43 H<n>`, with `H` equal to `T`. `G49` is the line before `M30`. Still never emit `G28`, `G30`, a second work offset, `M98`, or `M99`.
2. `error-text` stays `#FF5A5F`. Strokes and fills stay `#E82127`.
3. `part_revisions`, undo, and redo are in v1.
4. The program view has Copy only. No `.nc` download in v1.
5. Materials are `6061-T6`, `7075-T6`, `MIC-6`, `Delrin`, and `HDPE`. Feeds and speeds are placeholders from a public chart, and the operation text says so.

## Where a future agent should edit

| Task | Go here | Do not |
| --- | --- | --- |
| Change what a legal plate is | `Plate.Domain` limits and geometry | Re-implement the rule in Angular |
| Add a Grok tool | The action table in `Plate.Domain`, then the schema in `Plate.Grok` | Let the model write G-code or SQL |
| Change the look | `docs/design.md`, then `design/figma/screens.js`, then Figma, then `tokens.css` | Put a hex value in a component |
| Persist a field | EF model, a migration, and the ERD | A second store beside SQLite |
| Change the API | `backend.md` table, endpoint, regenerated TS types | Hand-edit the TS types |
| Run it | `compose.yaml`, `api/Dockerfile`, `web/Dockerfile` | A pile of manual processes |
| Health and config | `api/src/Plate.Api` | Re-implement the check in nginx or Angular |
